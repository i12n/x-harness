# TASK-1225 测试证据元检查（改了行为却没改测试）

> 来源：TASK-1220 设计稿里显式推迟的那条 —— 它需要 diff 接入证据管线，而 diff 在
> TASK-1221 已经就位。

## 1. 缺口

现在的证据链只回答两件事：仓库命令过没过、任务自带的 checks 过没过。
没人问过："这次改了生产代码，但**一个测试都没动**"——这是最常见的偷懒形态，
而且评审 agent 很容易漏（它看到的是"检查都通过了"）。

## 2. 拍板决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 用改动文件**路径**判定，不靠模型 | 与 TASK-1222 的风险分级同一原则：可复现、可审阅 |
| D2 | 触发条件：有非文档、非测试的代码改动 **且** 没有任何测试文件改动 | 纯文档/纯样式调整不该被判成"缺测试" |
| D3 | 只在**仓库配置了验证命令**时才升级为高风险 | 没有测试基建的仓库强求测试变更没有意义 |
| D4 | 结论同时给评审 agent 看（prompt 里明说）并进入风险理由 | 让评审有机会解释（例如"这是纯样式改动"） |

## 3. 落点

| 文件 | 改动 |
| --- | --- |
| **新增** `src/reviewer/domain/testEvidence.ts` | `assessTestEvidence(files)` 纯函数 |
| `src/worker/worker.ts` | 计算测试证据；满足 D2+D3 时并入风险理由（→ 强制人评审） |
| `src/reviewer/application/reviewerAgent.ts` | prompt 增加测试证据一行；input 增加字段 |

## 4. 验收（可执行）

1. 改 `app/globals.css` + `tests/mobile.spec.ts` → 不触发。
2. 只改 `app/page.tsx` → 触发 `missingTestChange`。
3. 只改 `docs/x.md` → 不触发（不是代码）。
4. 触发且仓库有验证命令 → 风险 `high`，理由写明；没有验证命令 → 保持 `low`。
5. 评审 prompt 里能看到这一行结论。

## 5. 回滚

判定集中在 `testEvidence.ts`；worker 里去掉两行注入即回到 TASK-1222 的行为。
